# CFIP 五槽全局跨池去重修复记录（2026-11-16）

## 结论

本次修复针对已有的五槽跨池重复，不改变 Cloudflare 五槽的手工内容，不改变候选门槛、主槽晋升规则、cron、PassWall、DNS 或 Sidecar 服务。

原有保护可以阻止新的候选写入其他槽位已占用的 IP，但无法主动收敛已经存在的 `auto/auto1/auto2` 与 `auto3/auto4` 跨池重复。因此重复可能长期保留，形成“新重复不产生、旧重复不消失”的状态。

## 实施内容

- 在 `sidecar-auto-sync.sh` 增加五槽全局重复规划。
- 按当前 `CF_RECORD_NAMES` 顺序保留较早槽位，只把后出现的重复竞争槽作为修复目标。
- 当前目标是竞争槽时，只从本周期真实合格的竞争候选中选择替代 IP。
- 替代候选必须满足现有竞争门槛，并且不得出现在其他四个槽位。
- 候选按现有质量排序选择，不引入新排序规则。
- 没有安全候选时继续使用既有报告状态 `awaiting_safe_competition_transition`，并在 detail 标记 `global_dedupe` 原因；不引入新状态名，不写 Cloudflare，等待后续自然周期。
- 主槽重复继续由既有主槽规划负责，本修复不绕过主槽三日基线和晋升门槛。
- 仍保持每周期最多更新一条记录，更新前后继续使用现有快照、重复保护、HTTP 门控和回滚路径。

## 测试范围

- 已有跨池重复且存在未占用合格候选：只规划后置竞争槽。
- 合格候选全部已被其他槽占用：失败安全，不生成写入计划。
- 重复目标属于主槽：交回既有主槽规划，不由跨池规划越权处理。
- 现有竞争槽排序、主槽重复修复、单记录转换、Cloudflare 回滚审计测试继续保留。

## 生产边界

- 本次只修改本地脚本、回归测试和记录文档。
- 未手工修改 Cloudflare 五槽。
- 未运行生产同步、Sidecar、扫描或诊断。
- 未重启 PassWall、Xray、DNS、Docker、Ollama、VM 或 Sidecar。
- `champion-pool.tsv` 仍是历史/辅助池，不被重新接入当前实时同步输入。

## 收口标准

通过本地语法检查、定向计划测试、全项目回归和 Sidecar 测试，并完成只读 IT 专家审核后，提交本次相关文件。生产层面的重复收敛仍由下一次自然周期按现有写入门控完成。
